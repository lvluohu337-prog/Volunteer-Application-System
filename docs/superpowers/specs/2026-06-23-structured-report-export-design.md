# 结构化推荐表导出设计

## 目标

把正式推荐报告中的结构化推荐表稳定导出到 PDF 和 Word，让导出产物可以直接作为交付件使用，而不再只是段落型摘要。

## 范围

本次只处理后端导出链路，不改接口、不改页面交互、不改报告生成数据结构。

- 保持现有 `/api/reports/student/{id}/export/pdf` 和 `/api/reports/student/{id}/export/word` 不变
- 保持 `report_data` 的现有字段结构不变
- 升级 `backend/report_exporters.py` 中结构化推荐表的表头和字段填充
- 补齐导出单测与集成回归

## 非目标

- 不改 `/reports` 页面布局
- 不重写 `planning_repository.py` 报告生成逻辑
- 不新增新的导出格式
- 不做 PDF/Word 的视觉精修，只保证结构、字段和稳定性

## 设计决策

### 1. 固定 7 列核心表格

正式院校专业推荐表统一导出为以下 7 列：

1. `院校`
2. `专业`
3. `专业组 / 代码`
4. `城市`
5. `最低分 / 位次`
6. `录取概率`
7. `风险提示`

其中：

- `最低分 / 位次` 合并导出，避免横向列数继续膨胀
- `录取概率` 优先取 `probabilityLabel`，为空时回退为 `-`
- `风险提示` 统一汇总 `riskLabel`、计划风险、调剂建议、选科限制中的可用摘要，优先保证交付阅读性

### 2. 分表策略保持不变

以下几个区块继续保留独立表格，不与主推荐表混合：

- 冲刺 / 稳妥 / 保底推荐表
- 第一志愿建议
- 备选志愿建议
- 不建议报考项

但它们的表格内容尽量对齐“院校 / 专业 / 专业组代码 / 城市 / 结果判断”这类可读模式，避免完全不同的导出风格。

### 3. 说明文字保留

现有导出中的说明段落、风险说明、合规提示、签字确认继续保留。  
本次不是“只导表格”，而是“把正式推荐表变成真正能交付的表格块”。

## 测试策略

### 单元测试

验证 PDF / DOCX 导出内容包含新的核心表头：

- `院校`
- `专业`
- `专业组 / 代码`
- `城市`
- `最低分 / 位次`
- `录取概率`
- `风险提示`

并继续包含：

- `正式院校专业推荐表`
- `第一志愿建议`
- `备选志愿建议`
- `不建议报考项`

### 集成测试

继续验证：

- 导出接口能生成真实 `.pdf` / `.docx`
- 导出记录可落库摘要
- `artifactType`、`renderEngine`、`downloadUrl` 等交付元数据不回归

## 风险与控制

### 风险 1：PDF 文本抽取不稳定

控制：

- 单测主要断言稳定标题和表头文本，不绑定整段自然语言顺序

### 风险 2：列太多导致 Word/PDF 表格挤压

控制：

- 把 `最低分` 与 `位次` 合并成一列
- 把多类风险信息合并成 `风险提示`

### 风险 3：改导出器时把现有其他表打坏

控制：

- 先写失败测试
- 跑导出单测
- 跑导出集成测试
- 最后跑后端全量测试

## 完成标准

满足以下条件才算完成：

1. PDF / DOCX 都能导出结构化 7 列核心推荐表
2. 第一志愿、备选、不建议报考项仍然正常导出
3. 导出相关单测与集成测试通过
4. 后端全量测试通过
